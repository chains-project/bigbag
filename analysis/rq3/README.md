# RQ3: cross-project transfer targets

Data for RQ3 (transformation generalizability) of the BigBag paper: 558 transfer targets for 24 breaking dependency updates (BU01 to BU24, as in Table III), and the 24 fixing transformations that were applied to them.

- `RQ3_transfer_targets.xlsx`: the same data as the CSV files, one sheet per file.
- `README.csv`: definitions of the columns, of a transfer target and of the transfer results.
- `Breaking_updates.csv`: the 24 breaking dependency updates (Table III), with BUMP commit, library, versions, SemVer, seed project, API change types, reproduced clients (transfer targets), fixed clients, fix rate, the test-baseline counts of the fixed clients, and the Total and Mean per transformation rows.
- `Transfer_targets.csv`: the 558 transfer targets, with the search that found each one, the search date, the client commit, fork information, the transfer result (FIXED, INCOMPLETE_MIGRATION, NO_MATCH) and, for fixed clients, the `mvn test` class before the update and after the transformation. 250 targets are FIXED, 257 INCOMPLETE_MIGRATION and 51 NO_MATCH.
- `Queries.csv`: the GitHub search queries per breaking dependency update, with dates and result counts where they were logged.
- `check_final.py`: recomputes `Breaking_updates.csv` (Table III) from `Transfer_targets.csv` and checks that both agree (`python3 check_final.py`, exit code 0 when all checks pass).
- `rules/`: the fixing transformation of each breaking dependency update, in a folder named by its BU id (`rules/BU01/` to `rules/BU24/`). Each one is the transformation generated by OpenCode/GPT-5.4-mini/JavaParser for the seed project of that update, and it was applied unchanged to every transfer target of the update. `rules/rules_index.csv` maps each BU id to its BUMP commit, library, versions, seed project and the generation run the transformation comes from.

The searches ran between 2026-04-21 and 2026-10-20, over all public repositories indexed by GitHub, with no filter on creation date, activity date, stars, size, archival status, or forks. We kept one candidate commit per repository and breaking dependency update.

## Applying a transformation

Each folder in `rules/` is a Maven project (`pom.xml` and `src/main/java/github/chains/Main.java`, JavaParser). The transformation takes the source root to rewrite as its argument:

```
mvn -q -f rules/BU01/pom.xml compile exec:java -Dexec.mainClass=github.chains.Main -Dexec.args="<client>/src/main/java <client>/src/main/java"
```

To reproduce a transfer result, check out the client at its `commit used`, bump the dependency of the BU to its new version, run the transformation of the BU on every source root of every module of the client (main and test sources), and run `mvn clean test-compile` (and `mvn clean test` for FIXED clients). A source root that the transformation cannot parse is left unchanged.
